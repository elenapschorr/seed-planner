# seed-planner

Web app to manage a private seed collection and to plan what to grow, where and when (sowing, planting out, harvest).
Portfolio project: keep it small and finished rather than large and unfinished.

## Stack
ASP.NET Core Razor Pages, C# / .NET 10, EF Core with PostgreSQL, Docker Compose. The garden editor is plain JavaScript (no framework) in `src/SeedPlanner.Api/wwwroot/js`. Azure deployment is prepared in `infra/` (Bicep).

## Layout
- `src/SeedPlanner.Domain`: entities, enums and all testable logic (plan calculator, allocator, geometry, monthly tasks, input parsing). No dependency on the web or the database.
- `src/SeedPlanner.Infrastructure`: `DbContext`, configuration, migrations.
- `src/SeedPlanner.Api`: Razor Pages (handlers only, no business logic), localization, JavaScript.
- `tests/SeedPlanner.Tests` (xUnit, Domain and Infrastructure only) and `tests/js` (Node tests for the editor modules).

## Conventions
- All identifiers in code and database are English; data in the database is English. The UI is localized (German, English, Russian; language from the browser, switchable). Every UI text lives in `SharedResource*.resx`, never in code.
- Multi-user: one database, `owner_id` on every record with a query filter per user; registration only with an invitation code.
- Clean Code. Use design patterns only where they solve a real problem. New logic goes into the Domain layer with tests.
- JavaScript modules are UMD with `create(app)`; shared state lives on the `app` object. Pure geometry and model modules have unit tests.
- UI rules (navigation, buttons, lists, forms, messages) are described in `docs/UI-CONCEPT.md` (German: `docs/UI-KONZEPT.de.md`). Foldable sections are closed by default. In lists the name is the link to the edit page. Design tokens are in `wwwroot/css/site.css` (paper white, ink, terracotta, serif headings).
- Migrations are generated by the developer:
  `dotnet ef migrations add <Name> --project src/SeedPlanner.Infrastructure --startup-project src/SeedPlanner.Api`
  (the model snapshot must come from EF; edit the generated code only to keep existing data).

## Domain notes
- Goal of the collection: reproduce seeds. F1 hybrids cannot be propagated, open-pollinated varieties can.
- Demand per person is stored on the plant type (Plants, RowMeters or SquareMeters) and can be overridden per user; rows and areas are converted to plants with the spacing of the variety.
- A plan has a period (`ValidFrom`/`ValidTo`, at most one year), its settings and its result. `PlanCalculator` computes plants per variety, `PlanAllocator` distributes them over the chosen pots and beds (neighbour rules, cold frame, shortage strategies). New beds are limited by the free garden area of the plot (`GardenArea`).
- Jobs per month (`MonthlyTasks`, page "This month"): sow, sow indoors, plant out, harvest; progress is stored on the plan line.

More detailed notes (current status, module descriptions) may exist in `CLAUDE.local.md`; that file is not committed.
